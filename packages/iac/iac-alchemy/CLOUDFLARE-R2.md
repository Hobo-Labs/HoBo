# Bounded R2 objects for JavaScript Workers

This opt-in target view exposes bounded R2 object read, write and delete to a
Bindle JavaScript Worker. It is not a WASI guest binding or a complete HoBo
blobstore or blob-events implementation. It does not provide subscriptions,
events, presigned URLs, object listing, ranges, multipart uploads, conditional
writes, or atomic compare-and-set. The host must reject applications requiring
those capabilities rather than accept them under this subset. In particular,
HoBo's inferred HTTP requirement includes `wasm`; declare and assess explicit
JavaScript requirements instead.

```ts
import { bindle, sessionReplay, type BindleRuntimeContext } from "@hobo/bindles";
import {
  bindleCloudflareWorker,
  cloudflareBindings,
  withCloudflareR2,
} from "@hobo/iac-alchemy/cloudflare/runtime";

export const neutralApp = bindle(
  "image-catalog",
  // Register and assess this host-defined name as the bounded subset below.
  { require: ["http", "blob-bounded-objects"], runtimes: ["javascript"] },
  (b) => {
    const images = b.bucket().allow("read");
    const web = b.web((context?: BindleRuntimeContext) => async () => {
      const image = await cloudflareBindings(context).bucket("images").read("logo.png");
      return image === undefined
        ? new Response("not found", { status: 404 })
        : new Response(image.body, { headers: { "content-type": image.contentType } });
    }).with(sessionReplay({ enabled: false })).dependsOn(images);
    return { images, web };
  },
);

// Issued and authenticated by the deployment host, not generated by app code.
export const cloudflareApp = withCloudflareR2(neutralApp, {
  images: { grantEpoch: hostGrantEpoch, bucketEpoch: hostBucketEpoch },
});
export default bindleCloudflareWorker(cloudflareApp, "web");
```

The same adapter view is imported by the host after establishing its immutable
source fence, then mapped and inventoried:

```ts
import { mapBindleToAlchemy } from "@hobo/iac-alchemy";
import {
  cloudflareNativeR2BindleMappers,
  cloudflareR2ProxySource,
} from "@hobo/iac-alchemy/cloudflare/r2";

const mappers = cloudflareNativeR2BindleMappers({
  workerModules: { web: absoluteAppModulePath },
  sourceFence,
  verifyBucket: (claim) => host.verifyR2OwnershipAndMigration(claim),
  verifyGrant: (claim) => host.verifyCurrentR2Grant(claim),
});
const mapped = mapBindleToAlchemy(cloudflareApp, mappers, {
  assessRequirements: trustedAssessRequirements,
});
const proxySource = cloudflareR2ProxySource("image-catalog", "images", {
  grantEpoch: hostGrantEpoch, bucketEpoch: hostBucketEpoch, allow: ["read"],
});
// Add proxySource and the exact application source to the composite guard's
// sourceRequirements. Inventory the Bucket, proxy Worker and application Worker.
```

A nonempty `.allow("read", "write", "delete")` subset grants exactly those
verbs. A Worker uses `bucket(name).read(name)`, `.write(object)`, and
`.delete(name)`; the latter two are unavailable without their explicit grants.
`read` returns `undefined` for a verified missing object or returns `{ name,
contentType, digest, size, body }`. `body` is bytes, `size` is the byte length,
and `digest` is the SHA-256 of the complete returned body, prefixed `sha256:`.
`write` requires exactly those fields, checks size and digest before dispatch,
and writes the content type plus its integrity metadata. Keys are at most 512
UTF-8 bytes; object bodies are at most 1 MiB. Content types must be nonempty
printable ASCII, at most 512 bytes. Existing objects without the adapter's digest
are read and hashed; objects without a supported content type or with an
inconsistent stored digest fail explicitly. Mutations are unconditional and may
replace an existing object. A failed or malformed mutation receipt is
`R2_MUTATION_OUTCOME_UNKNOWN`; the adapter never retries it. Before retrying,
the host must permanently fence the original operation and reconcile its effect.
Each body stream also has a ten-second read deadline and a limit of 4,096
nonempty BYOB reads. A smaller object delivered in excessively many fragments,
an unsupported stream, or a stalled stream fails explicitly; read failures are
reported as unavailable and an interrupted mutation has an unknown outcome.
Digest calculation and each native R2 call also have ten-second deadlines.
A timed-out provider call may still complete, so its source must be fenced and
drained before the host concludes that a mutation had no effect.

For a resource declared with `.allow("write")`, construct the digest from the
exact bytes being written:

```ts
import { cloudflareR2Digest } from "@hobo/iac-alchemy/cloudflare/runtime";

const body = new TextEncoder().encode("hello");
await cloudflareBindings(context).bucket("images").write({
  name: "greeting.txt",
  contentType: "text/plain; charset=utf-8",
  size: body.byteLength,
  digest: await cloudflareR2Digest(body.buffer),
  body,
});
```

The mapper creates an Alchemy `Cloudflare.R2.Bucket` and a private proxy Worker.
The app receives only the proxy service binding, whose exact operations are
checked again by the proxy. The trusted host must independently authenticate
and fence the proxy's complete source, dependencies, build, artifact, routing,
Worker bindings, account permissions and any alternate access paths through
provider completion. It must prevent callers from acquiring direct Bucket access
or invoking the proxy outside its intended grant. Byte reads use BYOB streams and
fail closed if the runtime cannot provide them. Native R2 and service bindings
are tested in workerd; the host must also bound upstream buffering and concurrency.

`publicAccess: false` does not remove unmanaged custom domains from an adopted
or existing Bucket. The host must independently inspect and remove or fence all
such domains, public endpoints, credentials and other alternate access paths;
declaring the proxy or disabling the managed development URL does not prove that
the Bucket is private.

`verifyBucket` is bound by the host to the exact tenant, account, stage and
stack. It authenticates ownership and the nonreused `bucketEpoch`, and proves a
fresh bucket is appropriate or that any old data has been migrated safely.
Earlier infrastructure-only mappings used the bare resource name: moving to a
scoped bucket creates a different Alchemy identity, and must not be mistaken for
an automatic data migration. Fence old access and complete and verify any needed
migration before authorizing the new identity or retiring the old resource.
Multiple Bindles with the same resource name may have shared that old bare
identity. The host must resolve historical ownership and any shared data before
treating either new scoped Bucket as an exclusive successor.

Alchemy can reconstruct updates and deletions from historical state without
running the current mapper, so the current `verifyBucket` and `verifyGrant`
callbacks alone do not authorize retiring an old proxy or Bucket. For every
historical effect, the host's composite `verifyPlan` must independently
authenticate the historical source claim and compare the prior-state digest for
every historical Bucket and Worker resource against its durable records. It
must also authenticate the old bucket epoch, grant, proxy, tenant, account,
migration status and retirement ownership, and explicitly authorize any prior
resource-type alias or rename. It must verify
that old credentials and routes are permanently fenced and in-flight work is
drained or reconciled, and keep those guarantees in force through completion.
Compute `hashAlchemyPriorState` from the independently authenticated record;
accepting the plan's presented digest by itself is not verification.

`verifyGrant` independently authenticates the exact Bucket, allowed verbs,
proxy identity and nonreused `grantEpoch`. Every changed or reissued grant,
including an A→B→A permission change, requires a fresh epoch. Before activating
a successor, the host must retire and fence old credentials and proxy routes,
and drain or reconcile all in-flight operations. The Worker module and mapped
Bindle must use identical Bucket and grant epochs. Callbacks report a host-enforced
authority; returning `true` alone does not establish these guarantees.

A supplied financial model must cover the Bucket, the proxy and app Workers,
requests, storage, data transfer and every other billable effect. The host must
independently enforce any bounds assumed by the quote; otherwise the ordinary
unknown-pricing policy applies. To use eventual KV in the same view, pass its
`verifyNamespace` and `verifyGrant` authorities in the mapper's `kv` option and
apply both explicit target views to the Bindle.
