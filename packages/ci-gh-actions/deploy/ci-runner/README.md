# Legacy monolithic runner image

The hermetic runner is built in two steps:

1. **Base** — `base/Dockerfile` (Debian digest pin, `system-packages.txt`, Docker CLI, pinned GitHub Actions runner bundle, Playwright's pinned Chromium headless shell under `/opt/pw-browsers` with `PLAYWRIGHT_BROWSERS_PATH`, UID 1000). A Playwright bump that changes the `chromium-headless-shell` revision in `playwright-core/browsers.json` fails `scripts/test/ci-runner-image-contract.test.ts` until `CI_RUNNER_PLAYWRIGHT_CHROMIUM` and the Dockerfile ARGs move with it.
2. **Toolchain** — locked `mise install` plus `mise --locked oci build` from repo-root `mise.toml` / `mise.lock` (one OCI layer per tool), so every configured tool is installed from a lockfile URL and verified against its checksum.

Shellcheck is pinned at 0.10.0 in `mise.toml` and locked for every supported platform in `mise.lock`. The runner image contract requires every toolchain entry to have checksums and URLs for the same complete platform set.

Before checking the contract, `.github/actions/ci-runner-preflight` uses the checkout's `mise.toml` to discover requested tools absent from the running image. By default it installs only those tools with `mise --cd <checkout> install --locked <tool>...`, logs their names and elapsed time, and then runs the full contract. **Main workspace plan** passes `install-toolchain: false` on runners that already ship the pinned toolchain: preflight then verifies `mise.lock` with `mise install --locked --dry-run-code`, compares each tool's active version with its lock pin, and fails closed on drift instead of installing. Whether or not any install was needed, it resolves each configured tool that `command -v` cannot already see with `mise which <tool>` and prepends that executable's bin directory to the current process `PATH` (and appends it to `$GITHUB_PATH` on GitHub Actions) for later steps; tools already visible keep their existing resolution and are not resolved again. This repairs an older runner without unlocked downloads; a healthy image performs no install. Probe failures name the exact command and distinguish spawn errors (including `ENOENT`), terminating signals, and non-zero exits with a stderr tail. Persistent failures require the image rebuild below.

Use `bash packages/ci-gh-actions/deploy/ci-runner/build.sh` on the box worker. If the content-keyed `hobo-ci-worker:<version>` is absent locally and `GHCR_TOKEN` is non-empty, the script logs in and pulls `ghcr.io/<owner>/<repo>/hobo-ci-worker:<version>` (repository from lowercased `GITHUB_REPOSITORY`, default `Hobo-Labs/HoBo`). Without a token it skips GHCR and builds natively without prompting. A pulled image becomes `:local` only after the same in-container runner contract as a native build; a pull miss or failed contract falls back to the native build. Every reuse or build removes the OCI layout and temporary archives, uses an ephemeral local registry, prunes BuildKit to `HOBO_CI_WORKER_BUILDER_CACHE_CAP` (default `4GB`), and retains only the current and previous unused `hobo-ci-worker:v*` tags plus `:local` and images used by running containers. `scripts/ci-runner-image-gc.mts` uses only Node builtins and the dependency-free selector, so this cleanup also runs before `pnpm install`. The daemon applies the same retention on its scheduled GC.

## Lockfile-keyed deps image

`scripts/ci/deps-key.mts` prints `<toolchainVersion>-<depsKey>`. The digest covers the lockfile, workspace config, optional root `.npmrc` and `patches/**`, the deps Dockerfile, build script and bucket generator, mise's Node and pnpm entries, and `linux/<arch>`. Each importer manifest is reduced to pnpm's dependency-layout fields: identity/version, dependency and dependency-metadata fields, `bin`, `directories.bin`, `publishConfig.directory`/`bin`/`linkDirectory`, platform/engine fields including `devEngines`, `packageManager`, `workspaces`, `overrides`, `resolutions`, and root-only `pnpm`. One normalizer serializes those fields with sorted object keys for both the hash and staged context, so metadata-only edits change neither the key nor BuildKit's `COPY . .` input. By default the toolchain comes from the checkout; `--toolchain <version>` selects it explicitly. The ts-autocode importer manifests must be present (`pnpm run pins:fetch ts-autocode`, or a recursive submodule checkout).

Build and promote on the box:

```bash
bash packages/ci-gh-actions/deploy/ci-runner/deps/build-deps.sh
```

The build stages those manifests, the bucket generator, and the job-side `scripts/ci/deps-layer.mts` link script into its Docker context. The link script is not hashed into the deps key. One BuildKit build runs `pnpm fetch --frozen-lockfile` with network access and lockfile integrity checks, then installs offline as UID 1000 at `/opt/actions-runner/_hobo_work/HoBo/HoBo` with `RUN --network=none`, using `store-dir=/pnpm-store` and `package-import-method=copy`, before rebuilding only the `allowBuilds` packages. Both stages mount the persistent host store as BuildKit cache `hobo-pnpm-store`, so a new deps key does not start with an empty store. Builds always use `docker build` on the default builder without `--load`, preserving that instance's cache and avoiding a whole-image tarball export; pruning uses `docker builder prune`. If `GITHUB_REPOSITORY` is set and `docker info` reports the containerd image store, they also import `ghcr.io/<repo lowercase>/hobo-ci-deps:buildcache` read-only with `--cache-from`; a missing cache is a no-op. Classic image stores log and skip the import. The publisher alone writes that cache after pushing the image, under the same containerd detection. Root lifecycle scripts remain the job install's responsibility; the exact-match skip path runs `scripts/ensure-ts-autocode-links.mts` explicitly, while CI already skips root hook installation. The install stage moves only the `node_modules` trees and `.git` skeleton into a separate output directory. `scripts/ci/deps-layer-buckets.mts` assigns each `.pnpm/<entry>` to one of 64 buckets by SHA-256 of its content-keyed entry name, then moves each bucket into an independent tree. The final stage uses the generator's 64 `COPY --link --chown=1000:1000` instructions plus one residual copy for workspace links, `.modules.yaml`, `.pnpm/lock.yaml` and `.git`. Run `node --experimental-strip-types scripts/ci/deps-layer-buckets.mts --write` after changing that section's generator; `--check` and the contract tests reject drift. Entry order is sorted, all copied mtimes are touched to the fixed `SOURCE_DATE_EPOCH=0` (not the commit time, which would change every bucket digest), and `--rewrite-timestamp=true` is used only when the default `docker build --help` advertises it; otherwise the fixed epoch and explicit `touch` are sufficient. Unchanged entries keep the same bucket across lockfile changes, so registries can reuse unchanged layer digests instead of receiving one monolithic payload. No deletion pass, fetch store or staged manifests enter the shipped image, and the workspace path is unchanged. Labels `hobo.ci.deps-key` and `hobo.ci.toolchain` let the worker reject a stale layer. The fetch stage is never tagged as an image. Actual digest reuse and compressed push sizes must be measured on the box. A clean offline-install probe with `libc: ["glibc"]` did not remove `@rivetkit/engine-cli-linux-x64-musl` (85 MB), because that package declares no `libc` metadata and its static binary may be intentional on glibc. The architecture config and runtime dependency set therefore stay unchanged rather than claiming an unsafe or ineffective size cut.

The script builds on the checkout-computed `hobo-ci-worker:<toolchain>` when present. If that tag is absent, it reads the `v[0-9a-f]{12}` tag on `hobo-ci-worker:local`, logs the fallback, and passes that toolchain to `deps-key.mts --toolchain`, so the base image, key, and labels agree. It fails only when neither the computed image nor a versioned local-worker tag exists.

Every main push runs the workflow's deps job. After checkout and key computation, one inspect compares `hobo-ci-deps:local`'s `hobo.ci.deps-key` label; an exact match skips resolution, promotion and build. An exact keyed local hit returns before the build and can promote the existing image immediately; a matching `:local` whose keyed tag was pruned is retagged instead of rebuilt. Before a new build moves `hobo-ci-deps:local`, the script streams the staged manifests into the candidate and requires `pnpm install --frozen-lockfile --offline --config.confirmModulesPurge=false` to print `Already up to date`. The verification container uses an empty, UID-1000-owned tmpfs at `/pnpm-store` instead of mounting the host store. Every event can reuse a local or GHCR hit; `--no-promote` builds and verifies a new PR candidate without moving `:local`, and PRs never push GHCR or export cache. The deps job has `packages: read` and logs in for the registry cache before a build only when its token exists. The separate `ci-deps-publish.yml` workflow runs after a successful main fabric run or on dispatch. It computes the same key, skips when neither the keyed image nor a matching `:local` exists, skips an existing GHCR manifest, and otherwise runs `publish-deps.sh` with a five-minute job limit and a 240-second `timeout` around `docker push`. The push uploads only blobs the registry lacks, skipping unchanged bucket layers. Afterward, a containerd image store lets the script rerun the same build on the default builder and export `mode=min` registry cache under a 120-second bound; the final bucket layers are already pushed, so the export adds only a cache manifest. Classic stores and unavailable buildx log and skip only that export. Its concurrency group cancels superseded publishes. Registry latency or failure affects only that workflow, never HoBo CI. Set `HOBO_CI_DEPS_BUILD_MEMORY_MB` to an integer of at least 512 to pass Docker's `--memory` limit to both the build and offline verification container; the isolated worker daemon sets this to 4096 by default and runs the script under `nice`/`ionice`.

Each keyed deps image is **6–10 GB**; the old tagged fetch intermediates were another 6–10 GB each and drove the box to 95% inode use twice. After every successful build or promotion, `scripts/ci-runner-image-gc.mts` uses the daemon's shared selector to keep at most the current key and newest previous `hobo-ci-deps:*` key by creation time. It never removes `hobo-ci-deps:local`, the current key, or an image used by a running container; it removes every unused legacy `hobo-ci-deps-fetch:*` tag and then runs `docker image prune -f` for dangling build layers. Cache-hit promotion in the workflow runs the same collector.

The install stage leaves an unborn git repository whose `remote.origin.url` is `https://github.com/Hobo-Labs/HoBo`. This relies on the pinned `actions/checkout` implementation: [`prepareExistingDirectory`](https://github.com/actions/checkout/blob/11bd71901bbe5b1630ceea73d27597364c9af683/src/git-directory-helper.ts) keeps the directory when `.git` exists and that URL matches; an unborn `HEAD` is treated as detached by [`isDetached`](https://github.com/actions/checkout/blob/11bd71901bbe5b1630ceea73d27597364c9af683/src/git-command-manager.ts), and `clean: false` skips `git clean -ffdx` and reset. All default-path box checkouts therefore set `clean: false`, enforced by `scripts/lint-actions.ts`.

On a push whose commit file lists contain no runner image input, the workflow skips `CI runner image (mise oci)` so Main full gate can start immediately. Missing file lists and forced pushes still run the job; a push with an image input builds it before either gate that needs it. The image job checks out at depth 2 for its `HEAD~1` diff. Full-history secret scans run in Main full gate, while pull requests keep their separate Secret scan job.

## Fallback Dockerfile (`Dockerfile.monolithic`)

Use only when `mise oci` cannot package a required tool (for example an **asdf** backend, a vfox plugin whose hooks write outside the install dir, or **rust** from a non-mise rustup). HoBo’s pinned set (`cue`, `gitleaks`, `node`, `pnpm`, `shellcheck`, `syft`, `turbo`) uses aqua/core backends and is intended to stay on the OCI path.

If you must fall back:

```bash
version="$(node --no-warnings scripts/ci-runner-image-version.mts)"
candidate="hobo-ci-worker:${version}"
if ! docker image inspect "${candidate}" >/dev/null 2>&1; then
  docker build -f packages/ci-gh-actions/deploy/ci-runner/Dockerfile.monolithic \
    -t "${candidate}" .
fi
docker tag "${candidate}" hobo-ci-worker:local
node --experimental-strip-types --no-warnings scripts/ci-runner-image-gc.mts "${version}"
cap="${HOBO_CI_WORKER_BUILDER_CACHE_CAP:-${HOBO_CI_WORKER_BUILDER_KEEP_STORAGE:-4GB}}"
docker builder prune -f --keep-storage "$cap"
```

Document the tool and backend in a PR note and open a follow-up to restore the OCI layer split.
